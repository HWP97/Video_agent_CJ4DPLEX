## 어느 단계가 문제였나

기존 기본 F에서 새 기본 F로 바뀐 단계와 추가학습 단계에서 각각 성능이 달라졌다. epoch0을 제외한 과거 C01 선택기는 추가학습 전체가 나빠도 시작 모델을 남길 수 없었다. 실제 fold3 내부 예측과 완료된10epoch 기록에서도 이 문제가 확인됐다. 별도로 새 D03/D04 실행에서 모든 추가 epoch가 나쁜 실제 조건을 찾아 selected_epoch0, best.pt와 epoch0 가중치 동일, 저장 후 실제 예측 재생 동일을 검증했다. 역사적 counterfactual 계산과 새 학습 경로의 실제 검증은 receipt에서 구분한다.

## 수정으로 무엇이 회복됐나

- fold1: D03 epoch5, D04 epoch5
- fold2: D03 epoch0, D04 epoch0
- fold3: D03 epoch0, D04 epoch0

D01의 ADE는 1.057876이고 D03은 1.058969, D04는 1.058973다. epoch0 포함은 손해인 학습을 거절할 수 있게 하지만 최종 평가 개선을 보장하지 않는다. D03/D04의 parent 가중치·초기 점수·RNG·epoch별 배치 순서는 같고 D04는10개 parameter의 실제 optimizer moment/step을 복원했다. 이 두 조건 차이는 optimizer 상태 차이로 제한한다. D02는 과거 lr와 epoch0 제외 정책이 함께 달라 완전한 단일 요인 대조가 아니다.

- fold1, seed20261110: 두 분리 최악 비율 epoch20, 한 분리 최소 ADE epoch25

- fold3, seed20261111: 두 분리 최악 비율 epoch25, 한 분리 최소 ADE epoch25
- fold3, seed20261110: 두 분리 최악 비율 epoch5, 한 분리 최소 ADE epoch5

동일 후보 풀1/3/5/10/20/25epoch에서 각 모델이 학습하지 않은 원본 그룹의 ADE/Kalman 비율을 계산했다. 두 내부 분리의 최악 비율로 고른 정책과 기존 한 분리 최소 ADE 정책을 모두 같은 두 seed로 비교했다. 각 fold는 자기 train의 결과만으로 선택했다. epoch별 재학습 없이 각 궤적에서 checkpoint를 저장했고, 전체 train refit 이전에 모든 선택을 동결했다. 세부 수치와 분리별 차이는 CSV에 남겼다. 두 seed의 최종 평가 차이는 같은 정책에서도 선택 epoch가 달라질 수 있어 순수 seed 효과로 읽지 않는다. 같은 분리·같은 epoch의 seed 대조는 내부 CSV에서 확인한다.

기준 seed20261111에서는 두 그룹의 최악 비율 규칙도 세 fold 모두25epoch를 선택했다. 추가 검증 그룹을 넣었다고 짧은 학습이 자동으로 선택되지는 않았다. 이 정책의 최종 ADE/FDE/충돌률은 1.059743/2.158558/22.140811%다. 내부 그룹 선택과 최종 영역의 일반화 차이가 남는지 이 수치와 과거 F 참조를 함께 보되, 평가 결과로 epoch를 다시 고르지 않았다.

이번 조건 중 기존 F의 ADE/FDE/관측 이웃 충돌률을 모두 회복한 조건은 없다. 따라서 기존 최선의 복원을 달성했다고 보고하지 않는다.

과거 F는 외부 개발 선택·다른 학습 길이·seed가 함께 다른 역사적 참조다. 이번 통제 실험에서 얻은 차이와 그 역사적 점수 차이를 특정 한 요인의 인과효과로 합치지 않는다. fold3의 train 원본 그룹은3개로 적어 두 분리의 일반화 판단에는 한계가 있다. G/P/U, 새 gate·충돌·증류 구조와 추가 탐색은 실행하지 않았다.

## 검증과 산출물

관측만 읽는 별도 추론에서 조건별512사례를 재생했다. 동일 seed에서 정책 epoch가 같으면 같은 모델·예측을 재사용했다. F0는 진단 예측 SHA와 parent checkpoint를 확인하고 원본 scorer로 충돌률을 새로 계산했다. 완료 참조 예측과 기존 채점의 SHA·입력 순서를 확인해 재사용했다. 최종 점수는 파일별 배열을 다시 연결해 독립 집계했고 합산 방식과1e-12 이내로 일치했다. 원본/진단/기존 lock과 모델을 SHA로 보존 확인했다. 신규 유료 API0건, 모델 다운로드0건, 서비스 기본값 변경0건이며 ZIP을 만들지 않았다.

실행 중 fold1 D04의 선계산과 주 실행기가 같은 폴더에 동시에 진입한 편차1건이 있었다. 중복 완료3epoch와 추가 부분 epoch 가능성을 기록하고 주 실행기를 중단했다. 해당 폴더 원시 증거를 quarantine에 보존한 뒤, 완료 helper의 정상 epoch5 snapshot SHA와10epoch trace·실제 내부 예측을 확인해 최선 checkpoint를 복구했다. 복구 best는 epoch5 snapshot과 바이트 단위로 같아 가중치·optimizer·RNG 상태를 함께 보존한다. 복구를 위한 새 학습은0회이며 이후 전체 refit은 직렬로 수행했다. [실행 편차와 복구 증거](execution_deviation.json)에 상세를 남겼다.

전체 train에서도 epoch0을 택한 조건은 parent 가중치와 정규화 tensor가 완전히 같았다. 새 환경의512사례 자체 재생 오차는0이고, 역사적 F0 예측과의 전수 최대 절대차는 0다. 역사적 추론과 새 추론의 thread·결정론 설정 차이는 모델 수정 효과와 구분한다.

추론 첫 시작 전에는 새 helper common과 원 adapter common의 모듈명 충돌로 import가 실패했다. 예측 생성 전의 실패이며 새 helper만 고유 모듈명으로 격리했다. 학습 source·checkpoint·원본은 변경하지 않았고, 재시작한3fold 실제 추론으로 수정 동작을 검증했다. 원 실패 로그와 별도 추론 import 편차 기록을 보존했다.
